## Commands

```bash
npm run lint    # ESLint (flat config, v10)
npm run build   # esbuild bundle to dist/index.js + esbuild-plugin-license writes dist/licenses.txt
npm test        # Jest unit tests (mocked @actions/* deps)
npm run all     # lint + build + test
```

`npm run build` runs `node build.js`, which invokes esbuild with `esbuild-plugin-license` to produce `dist/index.js` and license attribution. ncc is no longer used.

## Architecture

This is a JavaScript GitHub Action that creates a build entry in Yontrack via the [Yontrack CLI](https://github.com/nemerosa/ontrack-cli). It reads action inputs (project, branch, build name, release label, run-info flags), maps them onto CLI args, and runs the CLI binary on the runner via `@actions/exec`.

**Key files:**
- `index.js` — source. A top-level IIFE loads pure-ESM `@actions/*` packages via dynamic ESM import and calls `runAction({core, exec, github})`. The action's logic lives in `runAction` and the exported helper `setWorkflowRun` for testability.
- `dist/index.js` — bundled output (esbuild, CJS) committed alongside source changes. The runner executes this, not `index.js` directly.
- `dist/licenses.txt` — license attributions for everything in the bundle, generated by `esbuild-plugin-license`.
- `action.yml` — action metadata: inputs, `runs.using: node24`, `runs.main: dist/index.js`.
- `index.test.js` — Jest unit tests. Tests pass mock `core`/`exec`/`github` objects to `runAction` and assert on what gets called.
- `build.js` — esbuild driver.

**Why dependency injection:** All `@actions/*` packages at the latest majors are pure ESM. Top-level `require('@actions/...')` no longer works in CJS source. The IIFE loads ESM deps once at startup and passes them into `runAction`, keeping `runAction` synchronous to set up but trivial to test (no module-level globals, no mocking infrastructure).

## Release process

Releases are automated via `semantic-release` (`.releaserc`). Commit messages follow Angular convention. Every conventional-commit type triggers at least a patch release; `feat` is minor; `refactor` and any commit with a `BREAKING CHANGE:` footer is major.

The CI workflow on `main`:
1. Runs `npm run lint && npm run build && npm test`.
2. Runs the action against itself (`uses: ./`) as a self-test.
3. Runs `npx semantic-release` — produces `vX.Y.Z` GitHub release; `@semantic-release/git` commits the regenerated `dist/`, `CHANGELOG.md`, `package.json`, `package-lock.json`, and `action.yml`.
4. Force-updates floating `vX` and `vX.Y` tags to point at the new release SHA.
